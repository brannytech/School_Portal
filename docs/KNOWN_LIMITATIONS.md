# Current limitations

23 October 2026. **Phases 0–3 complete within documented scope; Phase 4 next, not started.** See [Phase 3 report](PHASE_3_REPORT.md) for acceptance evidence and [risk register](RISK_REGISTER.md) for remaining platform risks.

- Studio supports the foundation block set plus formatted text and inline/display maths. New image/private-media/audio/download/diagram block editors and richer worked-step interactions remain follow-up scope; existing resource-upload workflows remain available. All twenty master-brief block editors are not complete.
- Structured lesson text stays read-only in the legacy weekly form; use Content Studio to edit it. History compares publication snapshots, not character-level collaborative changes.
- Offline unsaved edits remain only in the open editor's memory. Refresh/close after failed saving can lose them despite warnings; this is not full offline editing or cross-device draft recovery.
- Graphs, coefficient sliders and seven mathematical toolkits are available. Graphs use bounded sampling; exact feature recognition is limited to linear/quadratic expressions, with recognised polynomial intersections. Very narrow/oscillatory features may be missed. Geometry provides primitives, not a general constraint solver; polygon area assumes a simple noncrossing polygon. Matrix tools are bounded to 1×1 through 3×3; formula rearrangement demonstrates one equation. Existing topic tools, including log/antilog tables, keep their authorised learning context.
- Graph-construction feedback stays on the device and does not persist official marks/mastery. Student explorations reset on reopening. Blank drafts can be saved without questions; publication still requires at least one practice question per subtopic and one weekly quiz question. Formal assessment calculator permissions remain later scope.
- Advanced question interactions and new grading types remain Phase 4; the studio reuses existing supported answer inputs and grading rules.
- Existing question-bank order may be reconstructed by SQL IDs on restart; question content/identities and attempt snapshots are preserved. Current revision checks deliberately ignore incidental bank order while preserving document block order.
- Data/revision operations still use a single server process and the compatibility cache. Multi-replica writes and multi-school separation are not supported.
- Parent portal, new personalised intervention engine, subscription management and complete school report-card workflow remain later stages.
- Local build, 87 regression tests, maths audits, 11 interactive/blank-template browser checks, 14 studio checks and 8 foundation checks pass. Local fonts/editor bundles require the build step. Low-bandwidth/low-end-device performance, live PostgreSQL/S3/HTTPS, physical Android, comprehensive accessibility/load/security reviews and official curriculum/legal compliance remain unverified external or later-stage requirements.
