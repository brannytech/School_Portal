# Phase 2 — Teacher Content Studio implementation plan

23 October 2026 (Africa/Lagos). Phase 2 completed against the local gate below; see [acceptance report and limitations](PHASE_2_REPORT.md). This plan is retained for provenance. Graph authoring remains Phase 3, not started.

1. Extend `public/lesson-document.js` with a bounded `rich-text` block containing a strict TipTap JSON subset, safe links/marks and inline mathematical source. Keep version-1 plain blocks readable. The server validates mathematics through KaTeX as well as schema safety.
2. Add `client/studio-editor.js`, `client/math-input.js`, `client/math-render.js` and `scripts/build-editor.mjs` to bundle open-source TipTap, MathLive and KaTeX locally. Copy local fonts/styles/licenses. Lazy-load studio/editor/math input; students load display code only for equations.
3. Add `public/content-studio.js/.css`: week/subtopic selection and creation, contextual rich-text toolbar, block insert/edit/duplicate/delete/collapse/reorder with keyboard and drag controls, undo/redo, reusable block templates, equation palette and visual/source switching, bounded table/list/example properties and the existing practice/quiz fields.
4. Reuse `weekly-template` revision-protected drafts/publication. Autosave serialises saves, checks generation numbers and retains unsaved changes in memory through transient network errors. Do not persist private drafts to browser storage on shared devices. Warn before refresh/close with unsaved changes, show saved/error/conflict status and offer explicit reload/retry. Preview flushes the in-memory editor and uses the actual shared student renderer at 360/768/desktop widths.
5. Add scoped `weekly-history` GET and `weekly-restore` POST in `weekly-content.mjs`. Record snapshots of new publications, show older existing snapshots, restore as a new conflict-checked draft and retain all old versions/attempts. Use existing JSON storage; no destructive migration.
6. Integrate studio entry points in `public/weekly-course.js`, preserve the legacy weekly form and question metadata, and hydrate math in the student renderer. Update public assets/build checks/cache version without caching private API data.
7. Verify schema/XSS/link/math limits; API scope/CSRF/history/restoration/conflicts/restart/backup; actual teacher creation/format/equation/autosave/reopen/preview/publish and student reading; offline/conflicting edits and mobile widths. Run all regressions and maths checks. Document exact results and limitations before marking the gate passed.

Dependency evaluation: TipTap/ProseMirror has an official vanilla-JavaScript integration and structured JSON/history; Lexical would also require integration/bundling with a different content model. TipTap fits the existing block-document contract without a framework replacement. MathLive supplies visual mathematical input/virtual keyboard; KaTeX supplies local HTML/MathML display and a server parser with `trust:false`, expansion/size bounds and isolated macro state. Core packages use MIT licensing; installed package versions/licenses must be recorded from the lockfile before delivery. No paid TipTap services are required. Library selection does not itself constitute accessibility/device/security certification.
